# 按需要复用的动画模式

这些经验来自两条本地竖屏片及一份较长的 Canvas 动画源码分析，适用于当前路线；不是已经验证的通用视频框架。

## 时间与声音

- 事件表写开始时间、结束时间、文本、主体动作和声音。若按小节创作，统一换算为秒；内容时间有倍率时，画面、字幕、音轨一起换算。
- 每次 `render(t)` 重置变换、透明度与混合模式，再从 t 求位置。需要积分的轨迹先计算采样表，渲染时查表。顺序播放正常，不代表向后拖动也正确。
- 同一时间的内容和位置应一致，但浏览器读回后端切换、字体抗锯齿可能造成像素级差异；PNG 字节完全一致不能作为跨环境承诺。
- 模板用 `OfflineAudioContext` 一次生成原创电子音，预览播放这段缓冲，导出使用同一缓冲写 WAV。复杂长音轨再考虑分段；不要提前增加调度系统。
- 预览用 `AudioContext.currentTime - anchor + offset` 驱动画面。自动启声被拦截时，`resume()` 可能一直 pending，不要等待它才绘画面；先用 `performance.now()` 走视觉时间，真实点击后将同一音频从当前视觉时间接上。切换时钟、暂停和拖动要保留进度。
- WAV 按所有声道交错写采样，元数据与实际声道一致；左右声像不同才能验证真正的立体声，而不只是双声道复制。
- 循环 BGM 在结尾留约 0.5 秒余量或做淡出，避免下一循环开头突然冒出；最终混音仍应与总片长对齐。指定 BGM 直接集成，素材授权和是否允许修改按实际要求处理。
- 浏览器 `speechSynthesis` 的系统声音不会自动进入离线音轨。需要旁白时先取得用户要求并生成音频文件，再加入同一混音和时间轴。
- 角色电子音用不同音高、节奏、波形区分。给振荡器短起音和收尾包络，避免点击声；音乐让位给剧情提示音。真实听感需试听。

## 层次与动作

常用顺序为背景/视差 → 主体/轨迹 → 前景粒子 → 字幕/界面 → 少量闪光或震动。一个重要事件可以同时改变速度、亮度、标题和声音，不必为每个元素单独堆特效。

发光纹理、复杂形状、静态星云和模糊文字可先画到离屏 Canvas，再 `drawImage()` 复用。只有发现重复绘制明显拖慢时才加缓存。随机布局固定一次或使用 seed，避免多次启动产生另一部片。

## 已遇到的问题

- 像素角色起伏先对小于 0.5 的数取整会恒为 0；先乘实际像素尺度，再取整。
- 第四条聊天直接移除第一条并重排会突然跳位；对滚动偏移做短过渡，并裁剪聊天窗口。
- 子函数直接赋 `globalAlpha` 会覆盖父级淡出；需要继承透明度时相乘，并配对 `save()/restore()`。
- 1080 宽画布上的 26px 小字，缩到 360px 手机宽仅约 9px。小字不越界不代表可读；优先删次要文案或放大字号。
- 竖屏 `1080×1920` 与横屏 `1920×1080` 需要不同布局；侧边榜单可重排或隐藏，不能仅缩放裁切。
- 自定义中文字体必须先加载实际绘制文字。Google Fonts CSS 可能按字形分片；`fonts.ready` 或只测 Latin 不足。CSS 没加载时，`fonts.load()` 可能返回空数组而 `fonts.check()` 仍为真，模板将空结果视为失败；首帧和导出均不能悄悄换回系统字体。
- 本次 macOS/Chrome 实测中，自定义字体加载成功后，测试用的通用 `serif` 回退仍造成预览与导出基线度量不同；遇到这类差异先检查回退字体，已强制加载的自定义 Canvas 字体可使用明确字体名，并复核预览与成片静帧，不据此推断其他平台行为。
- 用媒体元素的旧工程在拖动后立刻读音频 `currentTime` 可能仍是旧值；先用用户选中的目标时间绘画面，再等媒体时钟更新。媒体元素读取外部 WAV/MP4 还需要支持分段读取的服务器。
- `file://` 页面用 `fetch()` 读取同目录音频可能被限制。需要双击预览时，可将用户授权的音频编码为 Base64 JS，用 `<script src="bgm.js">` 加载，并将生成的大文件加入作品 `.gitignore`；或使用真正的 HTTP 预览。包装不会改变素材授权。
- 数据快照、`data:` 页面或静态预览器不一定可靠执行音频、外链字体和 Canvas；用真实 Chrome 检查。测流畅度时将预览置于前台，后台 `requestAnimationFrame` 节流不等于导出帧率不足。
- 导出成功要看编码进程退出码，不能只看是否生成了文件。临时成片完成后才交付，保留已有文件。
- 长导出后台运行并报告进度，一次只跑一个重渲染。停滞超时观察最后有效进展，不用固定总时长截断仍在推进的导出；失败日志在清理前保留到测试记录。
- macOS 默认通常没有 GNU `timeout`（用户可能已自行安装）。需要限定测试用时可用 Python `subprocess.run(..., timeout=30)`，不要假定该命令存在。
- 用户素材、可编辑工程和最终成片应留在持久作品目录，不能依赖会话临时目录交付。

## 素材与证据边界

参考源码里的一份 `bgm.js` 实际包装已有 MP3，并非程序作曲；只复用 Canvas、离线音频、逐帧导出机制，不复制该歌曲。其竞赛名次由手写权重和动画运动决定，也不能当成模型能力数据。

已验证的项目曾使用“Playwright 截图 → FFmpeg”；本模板用“OffscreenCanvas JPEG → Python localhost → FFmpeg”减少依赖。二者都由同一个绝对时间画面函数驱动。修改现成作品时保留其有效工具链；新作只复用导出和检查机制，重新创作视觉、分镜、文案与配乐动机。知识动画逐项查证日期、人物与事件，无法解释的冲突不用，交付附出处。
